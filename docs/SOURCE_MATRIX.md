# 수집 소스 매트릭스 (운영 가이드)

게임별 공지 소스를 등록할 때 이 순서로 판별한다. 판별 결과는 관리 콘솔의 소스 config에 기록되므로 이 문서에는 **방법론과 진행 상태만** 남긴다. (ADR-012)

## 소스 등록 판별 순서

1. **RSS/Atom 확인** — `https://사이트/rss`, `/feed`, HTML `<link type="application/rss+xml">`.
   있으면 `rss` 타입으로 끝. 셀렉터 불필요.
2. **내부 JSON API 확인** — 공지 목록 페이지를 열고 브라우저 개발자도구 Network 탭(XHR/Fetch)에서
   목록을 내려주는 JSON 요청을 찾는다. 있으면 `api` 타입 + `items_path` 매핑.
   CSR(자바스크립트 렌더링) 사이트도 대부분 이 방법으로 해결된다.
3. **HTML 크롤** — 목록이 서버 렌더링(SSR)이면 `html` 타입 + CSS 셀렉터.
   등록 화면의 **테스트 수집**으로 제목·링크·날짜가 뽑히는지 확인 후 저장.
4. **전부 불가** — 로그인 장벽, 강한 봇 차단, 앱 전용 공지 등이면 소스 등록 없이
   **URL 빠른 등록**(소식 관리 → URL로 등록)으로 수동 운용.

등록 전 공통 확인: `robots.txt`에서 공지 경로 차단 여부, 이용약관의 크롤 금지 조항.

## 운용 정책

| 구분 | 정책 |
|------|------|
| 폴링 주기 | 활발한 게임 10–15분, 조용한 게임 30–60분. 조건부 GET이라 부담 낮음 |
| 자동 발행 | 새 소스는 검수 모드로 시작 → 1–2주 오탐 없으면 자동 발행 승격 |
| 셀렉터 깨짐 | 대시보드 `0건 지속` 경고 확인 → 테스트 수집으로 셀렉터 재조정 |
| 저작권 | 요약 3줄 + 원문 링크만. 전문 재게시·이미지 핫링크 금지 |
| JS 렌더 페이지 | 내부 비공개 API를 직접 호출하지 않고 공개 페이지 DOM만 확인. 로그인·CAPTCHA·차단 우회 금지 |
| 활성 시간 | 소스 config의 `active_start_hour` / `active_end_hour` / `utc_offset_hours`로 제한 |

## 니케 파일럿 (2026-08-25)

- 공식 목록: `https://nikke-kr.com/news.html`
- 방식: `html` + `render_js=true` (일반 HTTP HTML에는 목록이 없고 JS 실행 후 표시)
- 탭별 소스:
  - 중요 `sid=494`: 30분
  - NEWS `sid=496`: 60분
  - 공지사항 `sid=892`: 60분
- 운영 시간: 08:00~22:00 KST (`active_start_hour=8`, `active_end_hour=22`, `utc_offset_hours=9`)
- 수집 범위: 제목·표시 날짜·짧은 목록 요약·공식 상세 링크
- 제외: 상세 전문(`fetch_detail=false`), 공식 이미지(`image_url=null`), 비공개 CMS 직접 호출
- 발행: `auto_publish=false`; 모든 항목을 draft로 만들고 관리자 검수 후 발행
- 검증: 세 탭 각각 5건 수집, draft·원문 링크·이미지 미사용 확인
- robots.txt: 현재 404. 명시적 차단 파일이 없다는 뜻일 뿐 수집 허가를 의미하지 않음
- 권리/약관: `©Proxima Beta Pte. Limited ©SHIFT UP CORP.`. 상용 운영 전 메타데이터 수집·요약·딥링크 범위에 대한 서면 허가를 받는 것이 가장 안전함
